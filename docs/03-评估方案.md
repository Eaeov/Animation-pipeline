## 0. 为什么评估是本题的核心交付物

题面第二句就是 *"侧重对结果质量的评估"*，第三句 *"侧重 pipeline 的设计和评估"*。
而第四句给出了**唯一明确的价值判断**：

> **A/B 同 pipeline 都 75 分 > A/B 特调 90 分**

所以评估方案必须能回答一个问题：

> **这套 pipeline 稳不稳？** —— 而不只是"某一帧好不好看"。

**设计逻辑**：先问"要证明什么"，再设计指标。

| 要证明的命题 | 需要什么指标 | 归入哪层 |
|---|---|---|
| 输出在技术上是合格的 | 像素/结构/时序/画质 | L1 |
| 人确实换成功了 | 身份/动作/场景/伪影 | L2 |
| **pipeline 不挑片段** | **跨片段方差** | **L3** |

---

## 1. 三层评估体系

```
┌─────────────────────────────────────────────────────────────────┐
│ L3  稳定性        跨片段标准差 / 一致性指数 CI / 片段极差          │
│     ★ 直接回答题面 P1                                            │
├─────────────────────────────────────────────────────────────────┤
│ L2  语义质量      身份一致性 / 动作保留 / 场景保留 / 伪影          │
│     手段: VLM(qwen-vl-max) 三元对比评分 + 人脸相似度(可选)         │
├─────────────────────────────────────────────────────────────────┤
│ L1  客观技术       PSNR / SSIM / 时序闪烁 / 光流平滑 / 锐度 / 色彩  │
│     手段: OpenCV + scikit-image，全自动、零成本、可 CI              │
└─────────────────────────────────────────────────────────────────┘
```

### 1.1 为什么必须有 L1（已有 VLM 了）

VLM 有三个致命弱点，必须用 L1 兜底：

| VLM 弱点 | L1 如何补 |
|---|---|
| 打分有随机性 | 完全确定性，同输入同分数 |
| 需要 API、要钱、要时间 | 本地计算，秒级，免费 |
| 可能"看得出但说不出"细微闪烁 | 时序指标能精确量化帧间跳变 |
| 无法回归测试 | 可写单元测试卡阈值 |

### 1.2 为什么必须有 L2（已有 L1 了）

**L1 存在根本性的语义盲区**：

考虑两种情况：
- 情况一：模型**把主角换成了另一个人**，但换得很干净 → PSNR 低（因为人变了）但**任务成功**
- 情况二：模型**根本没换人**，只是加了个滤镜 → PSNR 高（因为几乎没变）但**任务失败**

**L1 无法区分这两种情况。** 只有语义层能回答"人换成功了吗"。

## 2. L1 指标设计与归一化

### 2.1 指标清单

| 指标 | 测什么 | 为什么对"换人"重要 | 归一化 |
|---|---|---|---|
| `psnr` | 像素保真 | 换人应尽量少动背景，PSNR 过低说明背景被重绘 | 20–40dB → 0–100 |
| `ssim` | 结构相似 | 比 PSNR 更贴人眼，抓结构性破坏 | ×100 |
| `temporal_stability` | 帧间亮度跳变 | **换人模型最典型失败 = 闪脸** | 闪烁量 6.0 → 0 分 |
| `motion_smoothness` | 光流变异系数 | 抓跳帧/抖动/动作断裂 | CV 0.8 → 0 分 |
| `sharpness` | 锐度保持比 | 抓模糊/糊脸 | 比值 0.2–0.8 → 0–100 |
| `color_fidelity` | HSV 加权色差 | 抓"换上去的人脸色不对" | 距离 40 → 0 分 |

### 2.2 关键设计：这是**有参照**的评估

本项目有一个**被很多同类作业忽略的优势**：我们手里有**原始 PV 片段**作为 ground truth。

所以 L1 不是无参照打分（那种分数没有绝对意义），而是
**「生成 vs 原片」的对比度量** —— 这使分数具备了明确的物理含义：

- `psnr` 低 → 画面被改动的幅度大（可能是换人成功，也可能是背景崩了 → 需 L2 判别）
- `temporal_stability` 低 → 帧间亮度在抖 → **明确是缺陷**
- `sharpness` 比值 < 1 → 生成比原片更糊 → **明确是缺陷**

### 2.3 时序闪烁指标详解（最重要的 L1 指标）

**为什么它最重要**：视频换人类模型的头号失败模式是"人脸闪烁" ——
单看任何一帧都正常，但连起来看脸在跳。**这是静态指标完全抓不到的**。

算法：

```
1. 抽帧 → 计算每帧平均亮度  b_0, b_1, ..., b_n
2. 二阶差分:            d2_i = |b_i - 2*b_{i-1} + b_{i-2}|
3. 闪烁量 flicker = mean(d2)
4. 辅助证据: 对 (b - mean(b)) 做 FFT, 高频能量占比

分数 = 100 * (1 - flicker / 6.0)     # 截断到 [0,100]
```

用二阶差分而非一阶：**一阶差分会把"缓慢渐变"（正常的光照变化）也当成闪烁**；
二阶差分只对"方向突变"敏感，正好对应"闪"这个现象。

### 2.4 评估器自检机制（保证评估本身可信）

**这是评估方案设计中最容易被忽略、但最重要的一环。**

问题：你怎么知道你的评估器是好的？

答：**用 MockAdapter 制造已知缺陷，看评估器能否检出。**

```python
# MockAdapter(jitter=0.0) → 完美复刻（仅复制）
#   → 预期 L1 各项接近满分
# MockAdapter(jitter=0.7) → 叠加模糊 + 亮度交替偏移（人为制造闪烁）
#   → 预期 temporal_stability / sharpness 显著下降
```

如果评估器对人为扰动**毫无反应** → **评估器是坏的**，所有分数都不可信。

测试位于 `tests/test_eval_sanity.py`。**这是"评估方案可信"的自证。**

## 3. L2 语义评估设计

### 3.1 四维度（对"人物替换"最本质的四问）

| 维度 | 问的问题 | 分数低意味着 |
|---|---|---|
| `identity_consistency` | 生成的脸像不像人设图里的角色？ | 换人没换像 / 身份漂移 |
| `motion_preservation` | 动作/姿态保留了原片吗？ | 动作被篡改 |
| `scene_preservation` | 背景/构图/镜头保留了？ | 场景被重绘（说明用错模型） |
| `artifact_level` | 有无糊脸/多手/穿模？ | 局部结构崩坏 |

### 3.2 保证 VLM 评分可信的四条措施

| 措施 | 实现 | 解决的问题 |
|---|---|---|
| **固定 rubric** | prompt 内嵌 0-100 五档锚点定义 | 防止模型自由发挥导致分数不可比 |
| **低温 + 固定 seed** | `temperature=0, seed=42` | 同输入尽量同分（可复现） |
| **强制 JSON 输出** | `response_format: json_object` | 避免自然语言歧义，可程序化解析 |
| **全程留证** | 存 `vlm_request_*.json` / `vlm_response_*.json` / 证据图 | 任何分数都可人工复核 |

### 3.3 rubric 锚点设计

```
90-100: 几乎无可挑剔, 可直接用于成片
75-89 : 质量良好, 有轻微瑕疵但可接受    ← 题面的"75分"落在这里
60-74 : 及格, 明显瑕疵但主体可辨
40-59 : 较差, 关键要素损坏
0-39  : 失败, 不可用
```

> **刻意与题面的"75 分"对齐**：让"75 分"在 rubric 里有明确语义
> ——「质量良好，有轻微瑕疵但可接受」，正是题目所说的"能用的下限"。

### 3.4 评分输入：三元对比（而非单图）

发给 VLM 的是三张图：**人设图 + 原片中间帧 + 生成片中间帧**。

为什么必须三元：
- 只给生成图 → 模型不知道"应该长什么样"，无法判断像不像
- 只给生成图 + 人设图 → 知道"该像谁"，但不知道"动作对不对"
- **三元才能同时约束"像人设"和"保留原片"两个要求**

### 3.5 调用失败的处理原则（重要）

**VLM 调用失败 / 未配置密钥时，返回 `value=None` 标记 `not_measured`，
绝不默认给中间分或 0 分。**

理由：给 0 分会**污染统计**（把"没测"当成"很差"），
给中间分会**伪造结论**。诚实标记 `N/A` 是唯一正确的做法。

## 4. L3 稳定性评估（本题胜负手）

### 4.1 三个核心数字

| 指标 | 定义 | 为什么需要 |
|---|---|---|
| **跨片段标准差 (std)** | 同一指标在 A/B/C 上分数的标准差 | 直接对应"都能到 75 分" |
| **片段极差 (spread)** | max - min 片段综合分 | 特调 pipeline 的极差会爆炸 |
| **一致性指数 (CI)** | `mean / (mean + k·std)`, k=2 | 把题目口径编码成一个可比较的标量 |

### 4.2 为什么需要 CI（不能只看 std）

`std` 单独看有问题：一个 pipeline 可能 mean=30 / std=2（稳定但很差），
另一个 mean=85 / std=8（好但波动稍大）。**只看 std 会得出错误结论。**

CI 的构造让**"低分"和"高方差"都被惩罚**：

```
CI = mean / (mean + 2*std)

mean=30, std=2  → CI = 30/34   = 0.88
mean=85, std=8  → CI = 85/101  = 0.84
mean=85, std=2  → CI = 85/89   = 0.955   ← 最好
mean=90, std=25 → CI = 90/140  = 0.643   ← 特调的危险信号
```

最后一行是关键：**mean 高达 90 但方差大 → CI 反而低**。
这正是题目说的"特调 90 分不如稳定 75 分"的数学表达。

k=2 的选择：表示 std 每增加 1 分，相当于均值降低 2 分。
即**波动的代价是分数代价的 2 倍** —— 体现"稳定性优先"的取向。

### 4.3 稳定性等级

| std 范围 | 等级 | 含义 |
|---|---|---|
| ≤ 5 | 优秀 | 跨片段高度一致，pipeline 对该类内容鲁棒 |
| ≤ 10 | 良好 | 一致性可接受 |
| ≤ 20 | 一般 | 存在明显片段依赖 |
| > 20 | 差 | pipeline 对片段内容不鲁棒 |

### 4.4 诚实性条款（写进代码的实现约束）

1. **只统计实际测到的指标**：`value is None` 的维度不计入，也不补零
2. **样本 < 2 时明确返回"无法计算"**，不伪造方差结论
3. **必须同时输出每片段的原始分**，让读者能自行复核，而不是只给聚合数
4. **必须报告最差片段分（worst）**，不能只报均值 —— 木桶效应是特调 pipeline 的特征

### 4.5 报告的结论必须是人话

L3 不满足于输出数字，还会给出判读（`_build_note`）：

```
片段极差 = 6.2 分 -> ★ 片段间差异小, 说明 pipeline 可复用性好 (符合题目 P1 要求)
```

或

```
片段极差 = 41.5 分 -> ⚠ 片段间存在明显差异, 说明 pipeline 对片段内容敏感, 可复用性存疑
```

> 评审不需要自己算，直接读到结论 + 证据。

## 5. 评估执行流程

```
runs/<run_id>/
   ↓
[1] 自动发现片段 (存在 05_assemble 的目录)
   ↓
[2] 重建 ClipPair (纯文件系统驱动, 不依赖内存态 → 可对历史 run 重新评估)
   ↓
[3] L1: 每个 evaluator 独立 try/except
      └ 单个指标异常不中断整体评估, 标记 not_measured
   ↓
[4] L2: VLM 三元评分 → 落盘 request/response/evidence
   ↓
[5] L3: 汇总所有片段的 {clip: {dim: score}} → 方差分析
   ↓
[6] 输出 report.json (机器) + report.md (人)
```

**设计要点：单点失败不阻断整体。**
任何一个评估器抛异常，只标记该维度 `not_measured`，
其余维度照常评估 —— 这样即使 VLM 挂了，L1+L3 仍能产出有效结论。

## 7. 已知局限（诚实声明）

| 局限 | 影响 | 缓解 |
|---|---|---|
| L1 无法判断语义成败 | PSNR 高低不能单独定论 | 靠 L2 补；两者需结合解读 |
| VLM 分数有波动 | 同一输入可能 ±3 分 | temperature=0 + seed；L1 交叉验证 |
| 无人脸相似度（可选依赖未装） | `face_identity_sim` 标 N/A | 需要时 `pip install insightface` |
| 未做时间一致性（光流扭曲度） | 无法捕捉"帧间身份跳变" | 列为扩展点 |
| 无人工盲评（时间不够） | 缺少人类主观基准 | 对照视频可供人工快速判读 |
| 三层权重未标定 | 综合分是等权平均，未必最优 | 明确声明为等权，不假装有优化 |

> **最后一条尤其重要**：综合分用等权平均，是因为**没有数据支撑任何加权方案**。
> 假装标定过权重比承认等权更不诚实。
