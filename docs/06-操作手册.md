# 素材就绪后的操作手册

> 本文件是**行动清单**，不是设计文档。
> 素材（PV + 人设图）准备好之后，从上往下照着做。

---

## 第 0 步：把素材放到位

```
assets/
├── source/
│   └── pv.mp4              ← 原始 PV（放这里）
└── character/
    ├── A.png               ← 片段 A 用的人设图
    └── B.png               ← 片段 B 用的人设图
```

**人设图的命名约定**（重要）：
- `A.png` / `B.png` → 分别给片段 A / B 用
- 或者放一个 `char.png` → A/B/C 共用同一张

**人设图要求**（不满足会被平台拒绝）：
- 200–4096px，宽高比 1:3–3:1，≤5MB
- **单人、面部清晰、无遮挡**
- 日式立绘风格（非真人、非写实）

## 第 2 步：扫描 PV，拿到推荐的切片方案

```bash
"$PY" -m anime_pv.cli scan --out runs/_scan.json
```

等 1-2 秒/镜头。输出类似：

```
【镜头排行 (按换人适配度)】
    #      起始     时长     适配度     运动     主体率     主体占比      锐度
    2    12.30   4.20   78.50   0.31   100%    8.2%   412.7
    5    28.10   3.60   74.20   1.85   100%    5.1%   380.2
   11    61.40   2.80    0.00  12.30     0%    0.0% 39821.0   ← 已排除
```

**怎么读这张表**：

| 列 | 含义 | 怎么看 |
|---|---|---|
| 适配度 | 0-100，综合评分 | 越高越适合换人 |
| 运动 | 平均光流幅值 | <2 算静止，>8 算剧烈（不适合） |
| 主体率 | 检出主体的帧占比 | 应接近 100% |
| 主体占比 | 主体占画幅比例 | 5-20% 比较理想 |
| 锐度 | 拉普拉斯方差 | 几百到几千正常，几万是噪点 |

**底部会直接给出可粘贴的 clips.yaml 片段。**

## 第 3 步：人工确认切片（不要跳过！）

`scan` 的推荐只是**推荐**。主体检测是显著性代理，不是真人脸识别。
**必须人工看一眼关键帧**确认切片合理。

```bash
# 抽出每个推荐片段的中间帧来看
"$PY" - <<'PY'
import sys, subprocess, pathlib
sys.path.insert(0, 'src')
from anime_pv.utils import video as V

# 按 scan 给出的 start/duration 填
clips = {"A": (12.30, 4.20), "B": (28.10, 3.60), "C": (61.40, 2.80)}
out = pathlib.Path("runs/_preview"); out.mkdir(parents=True, exist_ok=True)
for cid, (st, du) in clips.items():
    V.extract_frame(pathlib.Path("assets/source/pv.mp4"),
                    out / f"{cid}_mid.jpg", at=st + du / 2)
    print(f"{cid}: {out / f'{cid}_mid.jpg'}")
PY
```

然后**打开这几张图看一眼**：
- [ ] 主体（角色面部）清晰可见、没有被遮挡
- [ ] 切点不在镜头切换的瞬间（画面完整、不是闪白/闪黑）
- [ ] C 片段确实是"困难样本"（剧烈运镜/多人/遮挡）

如果推荐不理想，**手动调整** `configs/clips.yaml`。

## 第 4 步：填写 clips.yaml

把 `scan` 的输出粘贴进去，并补齐 `source` 元信息（合规要求）：

```yaml
source:
  video: "assets/source/pv.mp4"
  title: "作品名"
  season: "2026年X月新番"
  url: "https://官方PV链接"
  downloaded_at: "2026-09-23"

clips:
  A:
    start: 12.30
    duration: 4.20
    role: "baseline"
    complexity: "low"
    rationale: "主体清晰的静止中景, 建立 pipeline 上限基线"
  # B / C 同理
```

> 这些元信息会在评估报告里被引用，也是题面"合规声明"的要求。

## 第 5 步：dry-run 验证（不花钱）

先用 mock 适配器跑一遍，确认配置无误：

```bash
"$PY" -m anime_pv.cli run --clips A,B --adapter mock --tag dryrun
```

**期望**：五阶段全部 OK。如果报错，检查 clips.yaml 的 start/duration 是否超范围。

## 第 6 步：真实生成（省钱模式）

### ⚠️ 额度提醒

**免费额度仅 50 秒（std + pro 共享）**，超出后：
- std: 0.6 元/秒
- pro: 0.9 元/秒

**所以务必：**
1. 先只跑 **A 一个片段**验证链路（4.2s ≈ 2.5 元）
2. 确认无问题，再跑 B
3. C 看剩余额度决定

### 先跑 A

```bash
"$PY" -m anime_pv.cli run --clip A --adapter dashscope --mode wan-std --tag stdA
```

**预期耗时**：2s 视频约 30–60 秒（模型侧排队）。

**可能遇到的错误**：

| 错误码 | 原因 | 处理 |
|---|---|---|
| `DataInspectionFailed` | 内容审核拦截 | 换素材 |
| `IPInfringementSuspect` | 疑似侵权 | 换素材 |
| `InvalidParameter` | 参数越界 | 查 `doctor` 与 clips.yaml |
| 超时 | 排队久 | 适配器已内置指数退避重试 |

### 再跑 B

```bash
"$PY" -m anime_pv.cli run --clip B --adapter dashscope --mode wan-std --tag stdB
```

> **注意**：A 和 B 必须用**完全相同的参数**（除 clip 外）。
> 这正是本题要验证的"同一 pipeline"。
> 想确认的话：两条命令只有 `--clip` 不同。

### 有条件再跑 C

```bash
"$PY" -m anime_pv.cli run --clip C --adapter dashscope --mode wan-std --tag stdC
```

## 第 7 步：评估

```bash
# 先跑 L1 + L3（不额外花钱）
"$PY" -m anime_pv.cli --run-id <run_id> eval --layers L1,L3

# 再加 L2（VLM 语义评分，走 qwen-vl-max，会产生少量费用）
"$PY" -m anime_pv.cli --run-id <run_id> eval
```

**报告位置**：`runs/<run_id>/_eval/report.md` 和 `report.json`

### 看报告时重点看什么

| 看什么 | 为什么 |
|---|---|
| **CI 一致性指数** | ← **本题核心**。这就是"A/B 稳定 75 分"那个数 |
| **各片段综合分** | A/B 差距越小，说明 pipeline 越不挑片段 |
| **片段极差** | 直接的稳定性证据 |
| `temporal_stability` | 有没有"闪脸" |
| `not_measured` 项 | 诚实记录，不要当 0 分看 |

## 第 8 步：留存失败证据

从报告里找出**得分最低的片段**，把证据归档：

```bash
"$PY" - <<'PY'
import sys, pathlib, shutil
sys.path.insert(0, 'src')
run = pathlib.Path("runs/<run_id>")
fails = pathlib.Path("docs/failures"); fails.mkdir(parents=True, exist_ok=True)

# assemble 阶段已经生成了对照视频 (原片 vs 换人后, 上下堆叠)
for cid in ("A", "B", "C"):
    src = run / cid / "05_assemble" / "compare.mp4"
    if src.exists():
        shutil.copyfile(src, fails / f"case_{cid}_compare.mp4")
        print("已归档:", fails / f"case_{cid}_compare.mp4")
PY
```

再写一段文字说明：**哪一段失败了、失败表现是什么（闪脸/糊脸/没换/身份漂移）、
推测原因是哪一步**。

## 附：额度预算表

按免费 50 秒规划：

| 方案 | 片段时长 | 总计 | 说明 |
|---|---|---|---|
| 最小验证 | A=4s | 4s | 先跑通链路 |
| **推荐** | A=4s + B=4s + C=3s | **11s** | 留 39s 余量应对重试 |
| 充分 | A/B/C 各 6s | 18s | 仍有余量 |
| 危险 | 合计 > 45s | — | 重试就可能超额 |

> **不建议**：把整支 PV 都跑。题目明说"不关注质量将整个 PV 都跑了也没有意义"。
